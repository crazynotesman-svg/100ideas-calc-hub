## 线上 404 排查（计算器详情页）

- **现象**：`https://calc.100ideas.net/zh/calculators/travel/schengen-visa-calculator` 返回 Next.js 404（"This page could not be found."），首页/列表页正常。
- **根因**：`app/[locale]/calculators/[category]/[slug]/page.tsx` 设了 `export const dynamicParams = false`。在 Cloudflare Workers（OpenNext）部署下，动态段预渲染页的命中不可靠——预渲染 manifest 虽列出 12 个计算器页，但 Worker 的预渲染路由没命中其静态 HTML，请求落到按需渲染分支；`dynamicParams=false` 把"不在命中列表"的合法参数直接判 404。这是本项目唯一设了 `dynamicParams=false` 的路由，与"只有详情页 404"完全吻合。
- **修复**：改为 `export const dynamicParams = true`。合法 slug 走 SSG 命中或 Worker SSR 兜底（两者 SEO 完整），仅 `getCalculator` 返回空的非法 slug 才 `notFound()`。
  - 已提交 `2beb5d4`，待用户本机 `git push origin main` 触发重部署验证。
- **补充事实**：`calculators.config.ts` 实际只有 3 个计算器（schengen/fire/tdee）× 4 语言 = 12 页（page.tsx 注释"all 12 pages"是对的）。working memory 里写的"244 计算器"是误记——244 是四语言翻译字典的键数，不是计算器数量。
- **通用教训**：OpenNext→Cloudflare Worker 部署里，对动态段路由慎用 `dynamicParams = false`；宁可 `true` + 在 page 内用 `getXxx()` 失败即 `notFound()` 来正确拦截非法参数。

  - 新增 `config/ads.config.ts`：publisher ID + `ADSENSE_SLOTS` 映射表（逻辑名如 `schengen-sidebar` → 真实广告单元号，留空待填）。
  - 新增 `public/ads.txt`：`google.com, ca-pub-1952663885350547, DIRECT, f08c47fec0942fa0`。
- **激活广告还需用户操作**：AdSense 后台建"展示广告"单元 → 复制 `data-ad-slot` 数字 → 填进 `config/ads.config.ts` 的 `ADSENSE_SLOTS`（如 `'schengen-sidebar': '1234567890'`）。填之前页面只显示占位盒，不会报错。
- **两种路径**：① 手动单元（推荐，CLS 可控，已在 CalculatorLayout 预置 3 个位置/计算器：sidebar/in-content/footer）；② Auto Ads（仅需在后台开启，凭加载器即可自动插广告，但可能破坏 CLS/体验，SEO 站不建议）。
