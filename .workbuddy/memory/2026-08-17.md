## Bug fix: NumberField 删除末尾数字时回弹到 min（9acc2a4）

- **现象**：用户反馈 TDEE 数值输入框（如年龄 25）删除到空时会被回弹成 min 值（年龄 → "10"、FIRE withdrawalRate → "1"），无法清空末位、也无法输入中间态（"1." / "-"）。
- **根因**：旧 `NumberField` 每次按键都 `onChange(toNumber(e.target.value, min ?? 0))`，空串经 `toNumber` 落到 fallback `min ?? 0` → 受控 `value` 被强制为 min，下次渲染就显示 min（其首位数字如 "1" 让用户以为"有占位"）。这是受控 number input 的经典缺陷。
- **修复**：新增共享组件 `components/ui/number-field.tsx`，内部保留 raw-text 镜像：`value={text}`；空串/非法时不向上 commit（保留父级上次有效值、不污染 URL），合法有限数字才 commit；用 `lastEmitted` ref 区分"自己改的"与"父级外部改的"（hydrate/reset/preset/单位切换仍正常向下同步）。TDEE、FIRE 移除本地副本改引用共享组件；Schengen 用 `type=date` 字符串输入，**不受影响**。
- **验证**：typecheck 通过；`next build` 绿（36 SSG 页，preset 仍 SSG）；预渲染 HTML 抽查 age/weight/fire-age 的 `value` 为默认值，与客户端初始 `text` 一致 → 无 hydration mismatch。已推 `9acc2a4` 触发 Cloudflare 重部署。
- **注意**：空字段期间计算沿用"上次有效值"，用户键入新数字即更新；属可接受行为（非回归）。
