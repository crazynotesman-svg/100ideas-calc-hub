## GSC `sitemap-presets.xml` 无法抓取 → 根因修复 + 线上验证（commit 9d9d2e5 → push origin main）

现象：GSC 将 `sitemap-presets.xml` 标记为「无法抓取」；线上全部 `/preset/[scenario]`（dynamicParams=false 预渲染动态路由）返回 404，基础计算器页 200。
排除：Cloudflare Builds UI 的 Cache 开关无关（启用并重新部署后仍 404）。
根因：OpenNext for Cloudflare 默认 in-memory 增量缓存不跨 Worker 实例持久化 → 预渲染 preset 结果在边缘读不到 → 404。
修复：`open-next.config.ts` 配置 `incrementalCache: staticAssetsIncrementalCache` + `enableCacheInterception: true`（已写入 MEMORY.md 部署章节「关键坑」）。
推送：沙箱代理对 `github.com` 持续 502（api.github.com/cloudflare.com 正常），无法本环境 `git push`；由用户在自有网络执行 `git push origin main` 触发 Cloudflare Workers Builds 自动部署。

线上验证（全部通过）：
- 80/80 个 `sitemap-presets.xml` 内 URL → HTTP 200（此前全 404）。
- `audit:preindex`（live）：104 页，sitemap/robots OK，0 失败 → PASS。
- `audit:seo`（live）：24 路由全 200，hreflang/JSON-LD/标题描述合规，sitemap 24 项/120 hreflang 标签 → 0 违规 PASS。
- `audit:engines`（live）：TDEE/FIRE/Schengen 引擎全部 PASS。
备注：preindex 报告 104 页均带 `warn: hreflang serialized as hrefLang (camelCase)` 提示，属非阻断 cosmetic 警告，不影响 PASS。

后续（用户侧）：可在 GSC 重新提交 `sitemap-presets.xml` / 请求重新抓取，Google 通常数日内清除「无法抓取」标记。
